刚才为项目添加了一个小功能，但更大的更改需要更完善的流程。GitHub Copilot app 可以融入组织现有的工作流，帮助团队以正确的方式构建正确的内容。本课将开启一系列课程，带你体验典型的智能体驱动开发流程：从议题着手构建新功能，确保代码有效、行为符合预期，最终成功合并到项目中。

> [!NOTE]
> 后续功能开发将继续使用同一会话。通常，不同文件类型的工作会使用不同会话或 PR；这里为了聚焦核心概念，会采用简化流程。

本课将：

- 从 GitHub 议题启动新的智能体会话。
- 在 **Plan** 模式中明确需求。
- 使用 **Autopilot** 模式实现新功能。
- 审查代码。
- 在浏览器画布中手动验证功能。

继续开发此功能时，还会更新存储库指令、自定义现有的 quality-checks 技能、添加 MCP 验证、创建 QA 智能体，并创建功能 PR。

## 场景

Tailspin Toys 的游戏目录不断扩充，访客需要按类别和发行商筛选游戏。待办事项中的议题描述了该功能，但类别组合等细节需要在编码前达成共识。你将先用 Plan 模式确定这些决策，再授权 Autopilot 在明确范围内实现功能。

## 背景

在开发流程中引入 AI 编码智能体，并不会改变软件开发的基本原则，反而使这些原则更加重要！大多数开发人员都会遵循类似的流程：

1. 打开描述需求的已创建议题。
2. 制定要构建内容的计划。
3. 编写并审查代码。
4. 运行测试以验证代码。
5. 手动验证新功能。
6. 创建拉取请求 (PR)。
7. 代码通过审查且持续集成流程成功后，合并代码。

> [!NOTE]
> 具体流程因团队和组织而异，但大多数流程都与上述步骤类似。

遵循这种标准流程，可以确保 AI 生成的代码满足需求，并像手写代码一样经过审查。

## 会话模式

**会话模式**控制智能体的自主程度。可以通过提示词字段下方的下拉列表设置模式，并随时更改：

- **Interactive**：你与智能体协作。智能体提出更改建议，并等待你的输入后再继续。
- **Plan**：智能体先创建计划。你审查并批准计划后，智能体才会执行。
- **Autopilot**：智能体完全自主工作，包括编写代码、运行测试并不断迭代，无需等待输入。

先从 Plan 模式开始，审查计划，然后使用 Autopilot 实现计划。

## 从议题启动会话

开始筛选功能前，确认星级评分 PR 已合并，并且本地 `main` 已更新。

1. 在侧边栏的 **Sessions** 下，选择 Tailspin Toys 存储库文件夹，然后在存储库顶部导航中选择 **Issues**。打开 **Allow users to filter games by category and publisher**。这是已预置的议题，无需再次创建。
2. 选择 **New session**，并选择基于更新后 `main` 的**新工作树**。

   ![GitHub Copilot app 的议题视图截图，箭头指向 New session 按钮](../../../_images/app-new-session-from-issue.png)

3. 确认议题已关联到会话，并在模式选择器中选择 **Plan**。

> [!NOTE]
> 如果找不到 Node.js 或 npm，请让智能体运行 `node --version` 和 `npm --version`。如果它们在终端中能运行，但在会话中找不到，请检查应用的 PATH 或版本管理器设置，然后完全退出并重新打开应用。重试失败的操作和检查；不要仅仅因为智能体找不到 npm 就重新安装 npm。

## 规划筛选功能

规划可以在 Copilot 编写代码前审查实现方案。由于会话从议题启动，Copilot 已经获得功能请求作为上下文。发送以下提示词：

```plaintext
Build this feature.
```

回答 Copilot 的问题，并根据议题验收标准审查计划。确认计划涉及按类别和发行商筛选、无障碍控件、数据访问更改和测试。讨论任何不明确的行为，例如多个类别如何组合，或没有游戏匹配时应如何处理。

计划应包括使用项目现有工具运行 lint、单元测试、端到端测试和类型检查。计划应聚焦于实现和测试筛选功能；质量工作流完成后再创建 PR。批准计划前，请要求 Copilot 修改不符合预期的内容，并记录议题 URL 及达成一致的说明，供之后验证使用。

## 明确批准 Autopilot

确认计划符合预期后，选择 **Approve and implement this plan**，或当前版本中名称相似的选项。不要假定批准计划会自动切换模式，请确认当前模式指示器显示 **Autopilot**。

Copilot 将开始实现功能！你会看到它按计划逐步工作、生成代码并运行测试。

> [!NOTE]
> 批准后可能会立即开始实现，因此请先审查计划。如果 Copilot 报告缺少依赖项或端口冲突，请先解决设置问题，再将检查视为已完成。只停止自己启动的服务器。

## 审查并验证实现

生成的代码需要像其他代码一样，在合并前经过审查。现在检查代码并运行网站，确认一切正常。

1. 打开 **Changes**，检查筛选功能实现和测试。
2. 对照议题和已批准的说明审查结果，包括多个类别与发行商组合。确认更改符合存储库现有指令。
3. 检查 lint、单元测试、端到端测试和类型检查的结果。跳过的检查不算通过。
4. 修复失败并重新运行受影响的检查，然后再接受实现。Playwright 的端到端测试配置会构建并运行预览服务器，也可能复用本地服务器；确认受测服务器属于当前工作树，而不是上一课启动的服务器。

## 试用新功能

代码看起来不错，但实际运行情况如何？像之前一样启动应用，并在浏览器画布中打开网站。

1. 使用以下提示词请 Copilot 启动应用并在浏览器画布中打开页面：

   ```plaintext
   Start the app and open it in the browser canvas.
   ```

2. 稍等片刻，应用将启动，并在 Copilot app 中打开浏览器窗口。
3. 选择一个类别，确认结果与该类别匹配。清除筛选后，再选择发行商并确认结果匹配。
4. 同时应用类别和发行商筛选，并对照议题及已批准的计划检查结果。如果支持多个类别，还要验证已达成一致的组合行为。
5. 测试没有匹配游戏的组合，并检查空状态。清除或重置筛选条件，确认完整列表恢复。
6. 完成后，使用以下提示词请 Copilot 停止本会话启动的开发服务器：

   ```plaintext
   Stop the dev server and close the browser canvas.
   ```

## 为后续课程保留此会话

暂时不要创建或合并筛选功能 PR。请在第 4 至第 8 课继续使用此会话、工作树和分支。接下来会将自定义指令应用于筛选代码，再添加技能和 QA 改进，最后在第 8 课创建并合并合并后的 PR。停止开发服务器后，可以让会话保持空闲，并在下一课返回同一会话。
