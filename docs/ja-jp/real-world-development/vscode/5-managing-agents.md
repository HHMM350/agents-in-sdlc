GitHub Copilot をエージェントモードで使うと、コードベースの調査、変更の提案、ファイルの編集、コマンドの実行などを自律的に行います。この作業はローカル環境でリアルタイムに進むため、VS Code の Copilot Chat ではツール呼び出しやファイル編集を確認できます。差分をインラインでレビューし、個々の変更を承認または取り消し、エディターを離れずに追加のプロンプトを送って作業を調整したり広げたりできます。

この演習では、次の作業を行います。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューし、承認します。
- セッションの途中でエージェントに指示し、ハイコントラストモードに加えてライトモードを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティカスタムエージェントは、ハイコントラストモードを実装しています。作業中にデザインチームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライトモードの切り替え機能も追加します。新しい会話を始める代わりに、既存のセッションに指示を追加して機能を拡張します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが実行する各手順が表示されます。調査したファイル、実行したコマンド、提案した編集を確認できます。ファイル編集は差分と **Keep** / **Undo** の操作とともにチャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、各ツール呼び出しを確認します。ファイルの読み取りや編集、実行を求めるターミナルコマンドが表示されます。
3. エージェントがファイルの編集を提案すると、チャット内に差分が表示されます。
   - 変更を承認するには **Keep** を選択します。
   - 変更を取り消してエージェントに再試行させるには **Undo** を選択します。
4. チャット上部の **Files changed** の表示を開くと、セッション中にエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ターミナルコマンドの実行などで許可が必要な場合、エージェントは一時停止して **Allow** を表示します。内容を確認し、許可してもよいコマンドだけを承認してください。

5. エージェントがハイコントラストモードの実装を終えるまで待ちます。最後に、実施した変更の概要が表示されます。

## ライトモードを追加するようエージェントに指示する

ハイコントラストモードができたら、同じ会話でライトモードの切り替え機能を追加します。既存のチャットセッションを続けるため、エージェントは前の作業で得たコンテキストを保持しています。変更したコンポーネント、使用したスタイル設定、ローカルストレージのパターンなどが含まれます。

1. Copilot Chat の入力欄に、次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは前の作業を引き継ぎ、既存の変更を調べて、ライトモードの追加を提案します。
3. ハイコントラストモードのときと同じように、新しい編集を確認し、各差分で **Keep** または **Undo** を選択します。
4. エージェントの方向性が希望と異なる場合（たとえば、気に入らない方法で切り替え UI をリファクタリングしようとした場合）は、チャット入力欄の横にある **Stop** ボタンで停止し、明確な追加メッセージを送信できます。

> [!TIP]
> 進行中のセッションに指示を追加すると、最初からやり直すよりも速く調整できます。追加プロンプトを使って変更を依頼します（「CSS を簡潔にし、セレクターの重複ではなく CSS 変数を使ってください」）、方向を修正します（「3 つ目の切り替えを追加せず、既存の設定パネルにライトモードを組み込んでください」）、作業範囲を広げます（「両方の切り替えにキーボードショートカットも追加してください」）。

## 作業内容をレビューする

コミットする前に、エージェントが変更した内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連するテストが更新されているはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタムエージェントのアクセシビリティパターン（ARIA 属性、キーボード操作、セマンティック HTML、ローカルストレージによる設定の保存）が反映されていることを確認します。
4. 問題がなければ、Source Control パネルで変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードを使って、進行中のセッションを監視し、方向付けました。個々のファイル編集を確認し、承認または取り消して、コンテキストを失わずに追加プロンプトで作業を広げました。

このレッスンでは、次の内容を学びました。

- エージェントの作業をリアルタイムで監視する方法。
- 個々のファイル編集を承認または取り消す方法。
- 作業中のセッションに追加プロンプトを送り、方向を調整する方法。

[次のレッスン][next-lesson]では、アクセシビリティの作業をプルリクエストとして公開し、このラボを通してローカルのカスタムエージェントが行った変更をレビューします。
